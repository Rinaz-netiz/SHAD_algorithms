### Решение задачи:
**Идея решения**: Идеальное хеширование (Perfect Hashing) с помощью двухуровневой схемы для построения фиксированного множества, сложность проверки наличия элемента за `O(1)`.

Алгоритм строит хеш-таблицу без коллизий для фиксированного набора элементов.

1.  **Общая структура**. Используется два уровня хеширования:
    *   **Первый уровень:** Основная хеш-таблица (`FixedSet`).
    *   **Второй уровень:** Массив из `n` вторичных хеш-таблиц (`SecondaryTable`), по одной на каждую корзину первого уровня.

2.  **Построение (метод `Initialize`)**:
    1.  **Первый уровень хеширования**:
        *   Берется универсальная хеш-функция `h1`, которая отображает ключи в `n` ячеек (`n` — количество входных элементов).
        *   Все элементы изначального набора распределяются по `n` ячейкам в соответствии со значением `h1(key)`.
        *   Выбирается такая хеш-функция `h1`, чтобы минимизировать коллизии.  `Σ(размер_корзины_i)^2 <= C*n`, где `C` — константа (в коде `C=4`) (Это хорошая хеш-функция). Это свойство гарантирует, что общий объем памяти для всех таблиц второго уровня будет `O(n)`.
        *   Если сгенерированная `h1` не удовлетворяет этому условию, она генерируется заново, пока условие не будет выполнено. Математическое ожидание числа попыток — константа.

    2.  **Второй уровень хеширования**:
        *   Для каждой корзины `i` (результат первого уровня), содержащей `k_i` элементов, создается своя вторичная хеш-таблица размером `k_i^2`.
        *   Для этой таблицы подбирается своя универсальная хеш-функция `h2_i` такая, чтобы она распределила все `k_i` элементов своей корзины **без коллизий**.
        *   Если при размещении элементов во вторичной таблице происходит коллизия, хеш-функция `h2_i` для этой таблицы генерируется заново до тех пор, пока не будет найдена почти "идеальная" (безколлизионная).

3.  **Проверка на вхождение (метод `Contains`)**:
    1.  Для искомого элемента `number` вычисляется хеш первого уровня: `idx = h1(number)`, для нахождения ячейки, где может находится элемент
    2.  Внутри вторичной таблицы `secondary_tables_[idx]` вычисляется хеш второго уровня `h2_idx(number)`.
    3.  Проверяется, совпадает ли элемент, лежащий в этой ячейке, с искомым `number`. Так как на втором уровне нет коллизий, этой одной проверки достаточно.
    4.  Две операции вычисления хеша и один доступ к памяти, выполняется за `O(1)`.

**Сложность по времени:**
`n - количество элементов в наборе`

*   **Построение структуры (`Initialize`):**
    1.  Поиск подходящей первичной хеш-функции: `O(n)` (ожидаемая). Каждая попытка занимает `O(n)`, а ожидаемое число попыток — константа.
    2.  Инициализация вторичных хеш-таблиц: `O(n)` (ожидаемая). Суммарное время построения всех вторичных таблиц  `Σ(k_i^2)`, что, согласно свойству из п.2.1, не превышает `O(n)`.

*   **Итоговая асимптотика по времени (построение):** `O(n)` (ожидаемая)
*   **Итоговая асимптотика по времени (проверка вхождения `Contains`):** `O(1)` (в худшем случае)

**Сложность по памяти:**
`n - количество элементов в наборе`

1.  Хранение массива вторичных таблиц: `O(n)`.
2.  Суммарное хранение данных во всех вторичных таблицах: `O(Σ(k_i^2))`. Благодаря первичной хеш-функции, это гарантированно `O(n)`.

**Итоговая сложность алгоритма по памяти:** `O(n)`
